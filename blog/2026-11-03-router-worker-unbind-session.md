# 常驻靠解绑 Session，不靠把 ReAct 拉长

> 工程笔记。一篇一事。投放 Data Agent（TypeScript 宿主 + Pi 二次开发）。对照 DeepSeek Super-agent 里的 Router / Worker。

常驻 Agent 常被理解成「开一个更长的 Session」。群里没人 @ 它也会自己复现、提 PR——那件事成立的前提不是上下文更长，而是它已经从「人手动开会话」解绑成连续实体。本文只切这一刀：谁接入口，谁下场干活。

## 是什么

人手动开的一次任务，单 Session + ReAct 够用。常驻要同时接多件事、中途可打断、环境不丢，那是另一套系统。

切成两层：

- **Router**：唯一入口。人类消息、CI、评审先到这里；跨任务汇总，记清谁在干什么。可用轻量模型，高峰靠批处理。
- **Worker**：上下文隔离，挂满工具，用强模型。只向 Router 报状态；工具过程留在内部，别把整段 JSON 灌回协调层。

共享环境不靠口头约定谁先写文件，靠订阅同一事件流自行协调。外面再挂独立 **Watchdog**：有没有实质进展、方向有没有偏。

## 为什么

消融里有个刺眼对照：中性提示下，单会话五次都没调子代理，主会话被新消息打断；改成「优先委派」后才开始分工。

这说明：单会话里「分不分工」取决于提示词临场判断。双层架构把分工钉在系统层——Router 不许自己下场干活，Worker 不许直接接用户入口。

落到投放 Data Agent：编排与租约边界 ≈ Router；带工具的执行会话 ≈ Worker；外部验收 / 熔断 ≈ Watchdog。不是「再套一层聊天」。

## 怎么做

先钉四条，再谈框架名：

1. **入口唯一**：人类与半结构化事件一律先进 Router；同 PR / 同话题进同一 Thread，后续事件可直达已订阅的 Worker。
2. **上下文当缓存**：近期 Inline；超预算 Spill，只留引用与摘要；按对象 ID 链式按需取回。这是上下文导航。
3. **异步半双工**：耗时命令拆 start / stop，结果当新事件投回；别用同步工具调用卡住接新消息。
4. **脑手分离**：计算可上云、会话状态进库；未提交改动、私有凭据、内网执行留在端侧 daemon。

验收只问三句：谁接用户、谁有工具执行权、偏航谁先喊停。答不清，就还是把 ReAct 拉长。

## 收束

下次做「常驻 / 多任务」时，先画 Router 与 Worker 的边界，再选模型和框架。Loop 让模型转；解绑 Session 的是系统层的隔离与事件入口。Watchdog 不是可选装饰——没有它，偏航只能人肉盯。
