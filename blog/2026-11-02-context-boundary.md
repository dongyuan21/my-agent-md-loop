# 多轮上下文：权威在宿主投影，不在窗口堆历史

> 工程笔记。一篇一事。投放 Data Agent（TypeScript 宿主 + Pi 二次开发）。

多轮 Agent 跑起来以后，真正头疼的往往不是「会不会调工具」，而是十几轮之后窗口里到底该留什么。本文只讲这一点：上下文权威在宿主投影，不在历史消息堆里。

## 是什么

多轮上下文不是「历史越大越好」，而是宿主在每次喂模型前做的一次投影：Loop 负责转；窗口里看见什么，由宿主决定。

权威分两处：口径在 Wiki / 知识资产；窗口里最多留路径、表卡摘要、Verified SQL 句柄，需要再读资产。本 Session 只留任务、裁过的观察和未完成项；跨 Session 只沉淀指针，不沉淀抽象坏规则。

## 为什么

`while` 循环很好讲：有 toolCall 就执行，写回再问。难的是十几轮以后窗口会漂——整表 SQL、工具 JSON、失败摘要全堆进去，既贵又容易丢目标。

说「压缩」或「记忆」没有边界：谁改前缀、错了谁丢掉、大结果住哪，都没说清。政策若不在宿主钩子里，就只能靠模型临场发挥，压缩失败也会假装任务完成。

## 怎么做

压缩分级，不要一个开关：

1. 先裁工具载荷：砍体积大、对下一决策贡献低的字段；保留错误码、关键数字、契约字段名。
2. 再摘要已闭合轮次：短结论 + 证据指针；未完成 todo 留近端。
3. 大结果进外部目录，消息只留句柄；需要再 tool-read。跟人续聊用压缩档案，排障用全量 trace，两份别混。

系统提示和工具列表尽量稳；变的是投影后的可见消息。政策写在宿主钩子（与执行权、证据闸门同一层），模型无权改定上下文政策。满了按：裁 → 摘要 → 句柄 → 停。

## 收束

下次写 context 钩子时，先问三句：权威在哪、窗口默认有什么、满了按哪条梯子降级。答得清这三句，多轮就不会靠「压缩一下」糊过去。Loop 让模型转；宿主决定它每次看得见什么。
